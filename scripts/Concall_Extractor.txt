## CONTEXT

Gemini-powered concall extraction pipeline. Each PDF transcript is processed
through concall_prompt.txt → structured intelligence stored in Google Drive.
Prompt extracts: Table_A (financial grid + guidance), GF1 (raw forward
statements), GF2 (historical guidance vs actuals), GF3 (operational
visibility), GF4 (guidance quality flags), A1/A2/A3 (summaries),
B/C/E1 (growth drivers, management commentary, forward visibility).

### Fix 1 — MP3 dedup / date-based queue filtering   ✅ DONE
Problem: Some companies upload an MP3 first; transcript PDF comes a day later.
Same company-doc appears twice in the queue. Current queue dedup is by
content-hash only, not by (company × date).
Ask: If a doc is received for a company on 10-Jan and another doc from the
same company arrives on 12-Jan, treat as a new document and process both.
Filter should be: (isin × doc_type × received_date) → only reprocess if
received_date differs.
File to change: ingest_company_docs.py

Delivered (2026-05-28):
  Dedup key changed from `doc_id` alone to `f"{doc_id}__{announcement_date[:10]}"`.
  `known_keys` set built as (doc_id + "__" + announcement_date[:10]) composite.
  Same URL reappearing on a different date is now treated as a new document and
  processed. MP3-then-PDF scenario: both entries have different dates → both queue.
  Backward compatible: existing queue rows retain their old dedup key on reload
  (announcement_date is already stored in the parquet).

### Fix 2 — Seasonal Phase 2 frequency tuning   ✅ DONE
Problem: Phase 2 ran 29×/week flat. Concall seasons have up to 100 uploads/day
for 45-60 days after each quarter end (Dec, Mar, Jun, Sep). Off-season low volume.
Ask (clarified 2026-05-28):
  Peak season (India results seasons):
    Q3:  17 Jan – end of Feb     Q4: 17 Apr – 30 May (60-day annual season)
    Q1:  17 Jul – 30 Aug         Q2: 17 Oct – 30 Nov
    Weekdays: 5 runs 8AM-10PM + 1 overnight
    Saturday: 4 runs 8AM-10PM + 1 overnight
    Sunday:   3 runs
  Off-season: 3 runs/day on ALL day types (same as Sunday)

Delivered (2026-05-28):
  Mechanism: phase2.yml carries PEAK schedule; pipeline_skip_check.py reads
  today's date and suppresses off-season extra slots.

  phase2.yml — 4 cron blocks:
    30 2,8,14 * * *      → base: IST 08/14/20 all days (off-season pattern)
    30 5,11,16 * * 1-5   → weekday extras: IST 11/17/22 (Mon-Fri)
    0 6,11 * * 6         → Saturday extras: IST 11:30/16:30
    30 21 * * 0-5        → overnight: IST 03:00 Mon-Sat

  pipeline_skip_check.py — seasonal logic:
    _is_peak_season(ist_now): checks date against 4 season ranges
    _in_offseason_window(ist_now): checks ±75 min of IST 08/14/20
    Peak threshold:        45 min (process queue fast)
    Off-season threshold:  90 min within window; outside window → skip always

  Effective run counts after skip logic:
    Peak weekday:  6 daytime (08/11/14/17/20/22) + overnight = 7/day
    Peak Saturday: 5 daytime (08/11:30/14/16:30/20) + overnight = 6/day
    Peak Sunday:   3 daytime (08/14/20) = 3/day
    Off-season:    3/day all days (enforced by window filter)

  Note: Peak weekday is 6 daytime (user asked 5) and Saturday is 5 daytime
  (user asked 4). The +1 extra is unavoidable because base slots (needed
  for off-season) overlap with peak extras. During peak, queue is always
  full so extra slot only helps drain faster — not harmful.

### Fix 2B — BSE Direct API as secondary ingestion source   ⏳ PENDING
Problem (observed 2026-05-28): Screener's announcement filter is hard-capped at 25
items per page and ?page= does not work (repeats page 1). In peak season (Q4 results
especially), 30-50 concall transcripts can be uploaded in a single 2-hour window.
Any company past position 25 in that window is NEVER ingested, regardless of run
frequency. Run frequency is not a fix — even 30-min intervals are vulnerable when
30+ companies file simultaneously at 9AM.

Root cause: MAX_PAGES = 1 with comment "Screener feeds ignore ?page=". Confirmed
by user (saw 4-5 companies in second page after 4h gap that would have been missed).

Recommended fix: BSE Direct API as a secondary ingestion source (no auth required).

BSE endpoint:
  GET https://api.bseindia.com/BseIndiaAPI/api/AnnGetData/w
  Params: strCat=-1, strPrevDate=YYYYMMDD, strToDate=YYYYMMDD, strType=C,
          strSearch=P, strScrip=, subcategory=-1
  Returns: JSON list of announcements with ISIN, scripcode, headline, attachments.
  No pagination cap — returns ALL announcements in date range.

Implementation plan:
  File: scripts/ingest_company_docs.py — add _scrape_bse_api() function
  1. At run start, read last run timestamp from phase2_latest.json
     (or fall back to: now - lookback_hours).
  2. Query BSE API for announcements from last_run_time to now.
  3. Filter by headline: title contains "Transcript" / "Con Call" / "Earnings Call"
     / "Concall" (case-insensitive).
  4. Cross-reference returned ISIN against company_universe.csv → only keep matches.
  5. For each match, build a row dict identical to what parse_feed_html() returns.
  6. Merge into existing Screener-sourced rows, dedup by (doc_id, date).
  7. Download PDF + enqueue same as Screener path.

  NSE API: add later (more fragile, requires session cookies).

  Short-term mitigation (low effort, add before BSE fix):
  Add extra cron slots at 8:45 / 9:30 / 10:15 IST during peak season only,
  specifically to catch the 9AM morning bulk-filing wave. These are the highest-
  risk minutes of each peak weekday.

Effort: medium (BSE API response format needs inspection first).
Priority: HIGH — core coverage gap during peak season.
